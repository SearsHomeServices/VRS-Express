Request Description and Requirements
*
What elements does a solution need to include, and what requirements (business processes, etc) does it need to adhere to?
Summary: The VRS (Virtual Review System) platform needs bidirectional photo access with SRDM, keyed by service order number — both reading existing photos and writing new ones.

Background: VRS is a live digital authorization platform built for Sears Home Services that replaces the phone-based warranty repair authorization process. Field technicians submit repair authorization and NLA parts requests through VRS, and agents review them on desktop. The platform currently handles daily ticket volume across Sears Protect, Sears PA, and Sears Home Warranty (Cinch), saving the company an estimated $500K+/month in pre-screening for unrepairables and NLA.

The Problem: Technicians upload photos into TechHub forms (model/serial plates, estimate screenshots, appliance condition) as part of their normal service workflow. When they submit a VRS request, they must re-upload many of the same photos into VRS. This is duplicate effort on every service call. Additionally, when VRS agents request additional photos and the technician uploads them in VRS, those photos don't flow back to SRDM — so the SRDM record is incomplete.

What We Need — Two-Way Photo Integration:

Direction 1 — SRDM → VRS (GET/Read): An API endpoint or data access method that accepts a service order number and returns all technician-uploaded photo URLs/data associated with that SO. VRS would call this when an agent opens a ticket, displaying the SRDM photos alongside VRS-submitted photos in the agent review interface. This is read-only — VRS will not modify SRDM photo data through this path.

Direction 2 — VRS → SRDM (POST/Write): An API endpoint that accepts a service order number plus a photo file (or URL to our cloud storage) and associates it with the correct service order record in SRDM. When a technician uploads additional photos in VRS (e.g., agent-requested follow-up photos), those photos would automatically post to SRDM so the complete photo set exists in both systems.

The goal is that a technician uploads photos once — in either TechHub or VRS — and both systems reflect the complete set.

Technical Details:

VRS is hosted externally (Node.js/Express on Replit) and would consume these endpoints via HTTPS

We already have an active Snowflake key-pair auth connection to PRD_TPMS.HSTECH — if the read side is better served through Snowflake (table/view with photo URLs), that works for Direction 1, but Direction 2 would still need a write API

Service order format: DDDD-SSSSSSSS

We need documentation on: authentication method, request/response format, rate limits, max file sizes, and supported image formats

Photos stored in VRS are in Google Cloud Storage with publicly accessible URLs — we can provide these URLs for the write direction if SRDM can ingest from a URL rather than requiring a file upload
